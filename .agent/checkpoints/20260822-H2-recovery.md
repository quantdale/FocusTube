## What changed (89a437e, e513234, 747b9cb, 2c7646d)

### Root cause A — configure single-flight test was nondeterministic (category B)
`ConfigCounter.operation` threw without any suspension point, so the eight
task-group callers never deterministically overlapped: a fail-fast attempt
settled `.failed` before later tasks entered the actor, letting them
legitimately retry (CI observed startCount 2). The production coordinator's
contract was correct.

Fix (AuthSessionTests + GoogleSignInAuthSession DEBUG seam):
- one-shot ReleaseGate + GatedConfigOperation hold the FIRST attempt open
  inside `.configuring`;
- new event-driven `notifyWhenWaitersReach(_:)` watcher (continuation-based,
  no polling/sleeps) resumes the test exactly when seven callers are parked
  as waiters;
- release then fails all eight from ONE operation; retry succeeds once;
  success stays cached.

### Root cause B — overlapping reconciliation races (category C: real bug + test reliance)
`DownloadManager.init` spawns `Task { reconcileOnLaunch() }` while tests also
awaited it directly. Concurrent passes double-fired transport reattachment,
wiped each other's buffered events via shared bookkeeping, and a late pass
could re-seed stale persisted bytes onto an already-settled task.

Fix (DownloadManager + DownloadCoordinator):
- reconciliation is genuinely single-flight AND runs once per manager
  lifetime (continuation-gate coalescing + completed-pass short circuit);
- `attachedRequestIDs` persists across passes; attached requests are never
  re-attached/re-seeded/replayed;
- replay-drain marker (`replayingRequestIDs`, wave 5): routing keeps buffering
  while a request's pre-attach buffer drains, so the drain is the SINGLE
  ordered applier — the mailbox consumer could otherwise direct-route stale
  deliveries mid-replay past newer buffered ones;
- drain-until-quiet sweep; unmark shares an actor turn with the empty
  snapshot so nothing strands;
- Core settle-guard: `.progress` is refused for settled tasks so late/duplicate
  deliveries cannot regress terminal byte counts, while terminal events keep
  applying in delivery order (pinned failed-behind-finalization contract kept).

### Regression coverage added
