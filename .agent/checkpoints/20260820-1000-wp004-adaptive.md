## What changed
- `Sources/FocusTubeCore/Media/AdaptiveSelection.swift`: `AdaptiveSelection.select1080` picks a 1080p native-playable video-only stream plus the first audio-only stream; returns `nil` when either component is missing or when resolution would exceed 1080p.
- `Tests/FocusTubeCoreTests/AdaptiveSelectionTests.swift`: deterministic selection tests (selects 1080 video+audio, nil without audio, nil without video, never >1080).
- `App/Download/AdaptiveMuxer.swift`: `@MainActor` native AVFoundation muxer using `AVMutableComposition` + `AVAssetExportSession` (passthrough). Typed `MuxError` (missingComponent/incompatible/exportFailed). No FFmpeg/yt-dlp/remote fallback.
- `FocusTubeTests/AdaptiveMuxerTests.swift`: deterministic proof mux fails with a typed error on non-media input.
- `FocusTubeTests/AdaptiveLiveSmoke.swift`: opt-in (`FOCUSTUBE_LIVE_SMOKE=1`) downloads both components through the URLSession path and muxes them; a native-mux incompatibility is recorded as a valid observed outcome (ADR review), not a fallback.

## Acceptance mapping
- suitable 1080p source selects compliant video/audio components — `AdaptiveSelection.select1080` + tests.
- components download independently — `URLSessionDownloadTransport` (per-component downloads in live smoke).
- native mux/export creates validated playable final media, or evidence triggers ADR review — `AdaptiveMuxer` + `AdaptiveLiveSmoke` (success or typed incompatibility).
- no FFmpeg/yt-dlp/remote fallback introduced — preserved; muxer refuses via typed errors only.

## Known failures or deferred items
- Live adaptive mux on a real 1080p source was not executed (no `FOCUSTUBE_LIVE_SMOKE=1` + network). If the native exporter rejects YouTube's container/codec, that is the expected trigger for an ADR review, not an unauthorized tool.

## Durable decisions made
