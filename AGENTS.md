# AGENTS.md — FocusTube Autonomous Engineering Contract

This file applies to every coding agent working in this repository.

## Source of truth hierarchy

When requirements disagree, use this priority order:

1. explicit user decision encoded in an accepted ADR or `docs/00-PRODUCT-SPEC.md`;
2. `AGENTS.md` and `.agent/OPERATING_CONTRACT.md`;
3. subsystem specifications in `docs/`;
4. current work packet;
5. existing implementation.

Code does not overrule a locked specification merely because it already exists.

## Mandatory behavior

- Read `.agent/STATE.yaml` at the beginning of every fresh session.
- Work against one named work packet at a time unless the packet explicitly authorizes parallel work.
- Keep `FocusTubeCore` free of UIKit, SwiftUI, AVKit, AVFoundation, SwiftData, and GoogleSignIn imports.
- Keep YouTubeKit behind the `MediaExtracting` boundary; feature screens must never call YouTubeKit directly.
- Keep YouTube Data API access behind `YouTubeAPIClient`/protocol boundaries.
- Model mutable download behavior as an explicit state machine, not unrelated booleans.
- Preserve deterministic test seams for network, extractor, authentication, clock, filesystem, and download transport.
- Use structured concurrency. Shared mutable service state belongs in actors; UI state belongs on `@MainActor`.
- Never put credentials, OAuth refresh tokens, API keys, cookies, or real Google account data in source control or fixtures.
- Never automate real Google login with a user's password/2FA secrets.
- Never introduce Shorts UI, a `/shorts/` route, vertical swipe-to-next behavior, or implicit autoplay-next.
- Never raise the download ceiling beyond 1080p without a new accepted ADR.
- Never add yt-dlp or remote extraction as a fallback.
- Never add FFmpeg merely for convenience. Exhaust native AVFoundation muxing for the supported ladder first.
- Never introduce a backend for functionality that is natively achievable on-device without an ADR proving the need.

## Quality discipline

Critical/High regressions block progress. A checkpoint may not be marked complete with:

- failing deterministic tests;
- an iOS target that does not build;
- a simulator launch crash;
- a download state transition that can corrupt or orphan final media;
- a path that can expose a blocked short-form video in Home/Search;
- leaked secrets;
- silent data-loss migrations.

Medium/Low debt may be deferred only when logged in `.agent/STATE.yaml` or a tracked issue with evidence and impact.

## Change discipline

Prefer small, reviewable commits aligned with a work packet. Do not mix unrelated refactors with feature work. Do not rewrite architecture opportunistically.

Generated files:

- `FocusTube.xcodeproj/` is generated by XcodeGen and must not be committed.
- derived data, simulator artifacts, test result bundles, downloaded media, local secrets, and generated credentials are ignored.

## Evidence format

When updating `.agent/STATE.yaml`, record concise evidence such as:

```yaml
evidence:
  - kind: test
    command: swift test
    result: pass
  - kind: ci
    workflow: ios-ci
    run: 123456789
    result: pass
  - kind: simulator
    artifact: home-launch.png
    result: pass
```

Do not claim evidence you did not observe.

## Completion protocol

A work packet is complete only when every acceptance criterion is either:

- proven with evidence; or
- explicitly marked not-applicable with a documented reason accepted by the governing spec.

After completion, update `.agent/STATE.yaml`, append a checkpoint record if the milestone gate was crossed, and select the next packet from `.agent/work-packets/INDEX.md`.
